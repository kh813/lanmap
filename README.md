# lanmap 🛡️

**LAN Host Manager & Security Detector**

`lanmap` は、社内LANや拠点間VPNに接続されたネットワーク機器・端末を自動検出し、**持ち込みPCや未承認端末、野良ルーターなどの接続を早期警戒してネットワークセキュリティを守る**ための単一バイナリ型Webアプリケーションです。

スプレッドシート感覚の一覧画面で全端末を俯瞰・管理できるほか、新規端末の**即時アラート通知（Google Chat / Slack / Teams / Discord / LINE）**、**ブロードキャストストーム異常検知**、**詳細プロファイリング（Web管理画面名・型番・SSL証明書期限・オープンポート）**、および **内蔵の24時間/7日間 Ping 死活監視・稼働率集計エンジン** を標準搭載しています。

---

## 🌟 主な特長

1. **シングルバイナリ・外部依存なし（完全自己完結・CGO非依存）**
   * Docker や Node.js、追加の外部監視サーバーは一切不要。Go と `modernc.org/sqlite` によるピュアGo実装。Web UI資材、高精細ベクターFavicon、OUIデータベースもバイナリ内に完全内包。
2. **安全・低負荷な自動スキャン & マルチNIC安全設計**
   * 一般ユーザー権限で動作する非侵入型 ICMP Ping、DHCPパケットパッシブ傍受、mDNS、NetBIOS、UPnP/SSDP、OUIメーカー推定。
   * **マルチNIC・仮想NIC安全設計**: 複数NIC環境（業務LAN/検証用LAN/VPN/Docker等）では、OSのルーティング情報から **Default Gateway を持つメインNICのみをデフォルトでスキャン有効化**。その他のNICは安全のため停止状態で自動登録され、左カラムの「`...`」メニューからワンクリックでいつでもスキャン対象に追加・一時停止を切り替え可能。
3. **未承認端末の即時 Webhook 通知**
   * 社内管理下にない未知の端末を検出した際、**Google Chat**、**Slack**、**Microsoft Teams**、**Discord**、**LINE Notify** へ即座にアラート送信。
4. **資産管理台帳（ホワイトリスト）CSV/TSV 一括インポート & 利用者名自動照合**
   * 管理PCのホスト名・MACアドレス・シリアル番号・**利用者名（所有者/社員名）**一覧を取り込むことで、検出時に自動照合・承認し、画面に `👤 利用者名` を表示。未知端末のみをアラート対象化。
5. **ブロードキャストストーム & 異常トラフィック自動検知**
   * ループ配線や故障端末の暴走、マルウェアによるLAN内スキャンをリアルタイム監視し、画面ハイライト & Webhook警告。
6. **📈 24時間 Ping レスポンス時系列タイムライン & 稼働ヒートマップ**
   * 各ホスト行にインライン埋め込みされた時間比例 SVG タイムライン（30分刻み）により、回線の瞬断やLAN内遅延の変動、未計測区間（停止期間）を一目で把握。
7. **📊 ホスト行クリック詳細モーダル & ⚡ オンデマンド即時 Ping 診断**
   * テーブルの行をクリックするだけで、**過去7日間の詳細な遅延推移グラフ（SVG・日付目盛り付き）**、**時間帯別稼働ヒートマップ（4時間毎）**、**稼働率・平均/最小/最大RTT・ジッター統計**、およびその場で即時疎通チェックが打てる「⚡ 今すぐPing診断」を備えた詳細モーダルを表示。
8. **🔍 瞬時（0ms）リアルタイム・キーワード検索 & フィルタリング**
   * IP、ホスト名、メーカー、モデル、OS、ポート番号、接続形態（Wi-Fi/有線）、承認状態などの複合キーワードで即座にインクリメンタル絞り込み。
9. **🔌 有線LAN / 📶 Wi-Fi 接続形態のスマート判定（デフォルト有線LAN推定・確定シグナル判定） & 手動上書き指定**
   * 同一L2サブネット内では無線APはL2ブリッジとして動作しTTL減衰やtracerouteホップが発生しない点、および有線PCでも環境によってPing遅延が揺らぐ実態を踏まえ、**「デフォルトを有線LANと推定し、モバイル機器（スマホ/タブレット）やスマート家電/IoT、ランダムMAC等の確実なWi-Fiシグナルを持つ機器のみをWi-Fiと判定する」**安全な判定モデルを採用。
   * ホスト編集モーダルから接続形態（自動判定 / 🔌 有線LAN / 📶 Wi-Fi）を自由に手動指定・固定することも可能。スキャン巡回後も手動設定は保持されます。
10. **ホスト詳細ホバーカード & 5大拡張プロファイリング**
    * IP/ホスト名にマウスを合わせるだけで、**Web管理画面名（`<title>`）**、**UPnP詳細型番・シリアル**、**TLS証明書期限（失効前警告）**、**mDNSモデル**、**オープンポート**、**Ping応答速度 & ジッター** を瞬時に確認。画面端での自動反転にも対応。
11. **OS重み付きスコアリング判定エンジン & DHCP Option 55指紋（信頼度・根拠表示）**
    * SSHバナー、mDNSモデル、Webタイトル、UPnP、OUI、Ping TTL、そして **DHCP Option 55/60 指紋データベース**（Windows 11/10, macOS, iOS, Android, Linux, プリンタ, ゲーム機等）を複合照合する重み付きスコアリング判定を搭載。判定の信頼度（`High` / `Med` / `Low`）バッジと客観的エビデンス（判定根拠）を画面に明示。
12. **🔔 設定画面での Webhook 即時テスト送信機能**
    * Google Chat / Slack / Teams / Discord の各 Webhook URL に対してワンクリックで疎通テスト通知を即時送信可能。
13. **🚀 ワンクリック＆コマンド一発の自動セルフアップデート (GitHub Releases 連携)**
    * Web UI の設定モーダルから「今すぐアップデートして再起動」、または CLI で `lanmap update` を実行するだけで、GitHub Releases から最新バイナリを自動取得し、安全にインプレース置換＆自動再起動。
14. **OSサービス対応 & 常時 HTTPS**
    * Linux (`systemd`), macOS (`launchd`), Windows Service への常駐登録コマンドを内蔵。初回起動時に自己署名TLS証明書を自動生成。
15. **📶 セグメントごとの DHCP IPレンジ設定 & 動的IP端末のスマート区別**
    * 各セグメントにDHCP動的割り当て帯域（例: `100-150, 180-200`、カンマ区切りで複数指定可）を設定可能。検出されたWi-Fi端末分布からの**自動推定サジェストやワンクリックプリセット**にも対応。
    * **手入力レンジ固定チェックボックス**: 手入力したDHCPレンジを固定し、端末マーク時の自動学習・自動調整による意図しない上書きを防止可能。
    * **警戒の固定IP帯未承認端末**（アンバー色ハイライト、`🟡 未承認` / `🆕 NEW`）と、**日常的に入れ替わるDHCP動的端末**（通常背景、`🔵 DHCP`、自動許可）を視覚的に明確に区別し、アラート疲れを防止。
    * **死活連動アイコン**: 稼働中固定IPは `🟢`、DHCPは `🔵`、未承認は `🟡`、異常・警告検知時は `⚠️`、将来の侵入検知用に `🔴` を予約。端末がLANからいなくなった場合（オフライン時）は、固定IP・DHCP・未承認の別を問わず即座に `⚪`（Down）に切り替わります。
16. **🎯 IP割当（DHCP / 固定IP / 不明）プルダウン & 監視対象ホスト（障害即時Webhook通知）**
    * **IP割当 3択プルダウン**: 「IP割当」列から `DHCP` / `固定IP` / `不明` を直接選択可能。DHCPパケット受信やDHCPプール判定により自動判別され、手動での固定IP指定も即座に反映。
    * **監視対象（障害検知アラート）**: 「監視対象」列のチェックボックスをONにした重要機器（基幹ルーター、NAS、サーバー、IP電話、監視カメラ等）は、死活障害（Down）または復旧（Up）を検知した際に Webhook（Google Chat / Slack / Teams / Discord）へ高優先度アラートを即時発報。
17. **⚪ オフライン端末表示（⚪） & IP交代時旧ホスト履歴保持（🕒 前回） & 表示/保持期間カスタマイズ**
    * **同一IP交代時の旧ホスト履歴保持**: DHCPリース等で同一IPに別端末（新MAC）が割り当てられた際、旧端末のレコードを上書き消去せず `⚪`（Down, `🕒 前回`）として残し、新端末を `🔵`（UP）として並行表示。IPの割り当て履歴を明確に追跡可能。
    * **表示期間ワンクリック切替**: メイン画面ヘッダーで `[ 🟢 オンラインのみ ]` `[ 🕒 直近3日 (既定) ]` `[ 📋 すべて ]` を瞬時に切り替え可能。
    * **DB保持期間（クリーンアップ）**: デフォルト3日（最大7日推奨、設定画面から1日〜365日または無効を選択可能）。
18. **🌐 国際化・多言語対応 (i18n: デフォルト英語 & ブラウザ言語自動切替 & EN/JP スイッチャー)**
    * グローバルな環境や多国籍チームに対応。**デフォルト言語は英語 (`en`)**。
    * 日本語ブラウザ環境（`Accept-Language`）では自動的に日本語 (`ja`) で表示。
    * メイン画面右上の **`[ EN | JP ]`** トグルスイッチによりワンクリックで言語を切り替え可能（Cookieにより選択状態が次回以降も永続保持）。
19. **🛡️ セーフモード（低ノイズ・IDS誤検知ゼロ監視）& OS適応型ポート診断**
    * **デフォルト動作はセーフモード**: 定期バックグラウンドスキャンでは Ping + ARP + DNS/mDNS のみで静かに監視。17ポートへの一斉TCP接続を行わないため、**各種セキュリティソフトやUTMから「ポートスキャン攻撃」と誤検知される心配がゼロ**。
    * **OS・機器プロファイル別 適応型（Adaptive）ポート選定**: ポート診断時も一律17ポートを叩くのではなく、Ping TTL（128=Windows, 64=Mac/Linux）、OUIベンダー、mDNSから相手のOS/機器種別を自動判別し、**必要な最小限（2〜5ポート）のみをピンポイントで調査**（MacにはWindowsのRDPや不要なメディアポートを投げずSSH/SMBを調査、WindowsにはMacのAFPを投げずSMB/RDPを調査、プリンタにはSSH/RDPを投げない安全設計）。
    * **オンデマンドポート診断**: 気になる端末がある場合は、ホスト詳細モーダルから「🔍 開放ポートを診断」ボタンを押すことで、その端末にのみ単発でポート開放状況やWebタイトル・証明書を調査可能。
    * **フルスキャンモード切替**: 設定画面から常時ポートスキャンを行うフルスキャンモードへの切り替えもいつでも可能。
19. **🚨 リモートアクセス・VPN待受監視 & サービス情報バッジ（Info）体系 & 警告手動抑止**
    * **リモートアクセス & VPN監視の強化**: 業務LAN内で不正に立ち上げられたVPNサーバー（`SoftEther 5555`, `PPTP 1723`, `OpenVPN 1194`）や緊急外部リモートツール（`🚨 TeamViewer 5938`, `🚨 AnyDesk 7070`）、リモート操作・平文ログイン待ち受け（`Telnet 23`, `Windows RDP 3389`, `macOS画面共有/VNC 5900`）を適応型プロファイルでピンポイント監視し、`🚨 緊急待受/VPN` や `⚠️ リモート待受` のセキュリティ警告バッジを付与。
    * **既知ポートの警告手動抑止（ホワイトリスト化）**: 社内正規サーバー（踏み台、VPNサーバー等）で意図して立ち上げているポートは、ホスト詳細モーダルの「🛡️ 警告を抑止」ボタンやホスト編集画面から簡単に警告を抑止（既知化）可能。抑止されたポートは警告バッジから外れ、端末ステータスアイコンも本来の正常表示（`🟢` や `🔵`）に復帰。
    * **正当な管理・インフラポートの Info 認識**: サーバー管理用の `🔑 SSH (22)`、Web管理画面（`🌐 80/443/8080`）、開発用ポート（`⚡ 3000/5000/5173`）、企業認証基盤（`🪪 Kerberos 88, LDAP 389/636`）、ファイル共有（`📁 445/548`）、プリンタ（`🖨️ 631/9100`）等は警告（`⚠️`）から除外し、端末の役割を示す「Info サービスバッジ」として安全に可視化。
    * **デイリー低ノイズ巡回 (24hオンライン連動 ＋ ランダムジッター)**: 毎日固定時刻に一斉スキャンするとノートPCのスリープで見逃したりUTMの定期ビーコン検知に引っかかるため、**「端末がオンラインである時間帯」** に **「1台ずつ順次（ポート間100msウェイト）」**、**「24時間 ± 数時間のランダム揺らぎ（20〜28時間間隔）」** で静かに自動巡回。
20. **⚡ DHCPパケット・パッシブ監視 & Wi-Fi接続ゼロ秒即時検知**
    * **ミリ秒単位の接続検知**: 定期Pingスキャンの巡回周期（数分間隔）を待つことなく、社員や来客がWi-Fiに接続したりLANケーブルを挿した瞬間に飛ぶ `DHCP DISCOVER` / `DHCP REQUEST`（ブロードキャスト UDP 67/68）をパッシブに傍受。
    * **100%確実なMAC・IP・端末名・OS自動特定**: BOOTPヘッダーから物理MACアドレスを確実に抽出し、端末が自己申告するホスト名（Option 12: `Taro-iPhone`, `MacBook-Pro` 等）、要求/割当IP（Option 50 / `yiaddr`）、ベンダー/OS種別（Option 60 / 55）を即座に特定。
    * **動的端末（`🔵 DHCP`）自動マーク & アラート抑止**: DHCPパケットを発した端末は確実に動的IP端末として `is_dhcp = 1` を自動付与。未承認端末の誤検知を防ぎつつ、セグメントのDHCP帯域自動学習ともシームレスに連動。
    * **セーフモード完全準拠**: パケットを一切送信せず「受信のみ」を行うため、セキュリティソフトやUTMから攻撃と誤検知されるリスクはゼロ。
21. **🛡️ IPv6デュアルスタック監視 & タグVLAN適応型 Rogue RA（不正ルーター広告）検知**
    * **IPv6近隣探索 & デュアルスタック自動集約**: All-Nodes マルチキャストPing (`ff02::1`) およびOS近隣キャッシュ（macOS `ndp`, Linux `ip -6 neigh`）からリンクローカル（`fe80::`）やGUA/ULAを自動集約し、同一MACのIPv4端末とシームレスに統合。
    * **タグVLAN（IEEE 802.1Q）vs ネイティブLAN適応型 Rogue RA 監査**:
      - **ネイティブLAN（Untagged）**: 未承認端末からの不正RA（MITM・通信乗っ取り攻撃）を厳格に検知し、`🚨 不正ルーター広告(Rogue RA)` として即時Webhook警報を発報。
      - **タグVLAN（802.1QサブIF）**: ゲスト用やIoT等の分離VLANの正規ルーターによる誤検知を完全に防止。監視対象外VLANのパケットは安全にスキップし、監視対象VLANでは `⚠️ タグVLAN未承認ルーター通知` として適切なガイダンス通知を実施。
      - 自マシンの物理/仮想MACアドレスや、OSのデフォルトゲートウェイを自動認識し誤検知をゼロ化。
22. **👤 端末所有者ヒント情報の安全・パッシブ収集 & 利用者名突合**
    * **台帳利用者名の自動紐付け**: ホワイトリストに登録された利用者名（社員名等）と自動照合し、画面に `👤 山田太郎` と表示。
    * **パッシブ所有者ヒント自動抽出**: mDNS や DHCP Option 12 で端末自身がブロードキャストしているホスト名（`田中's iPhone`, `Taro-no-MacBook`, `pc-suzuki` 等）から、プライバシーに配慮しつつ安全に推定ヒント（`👤 (推定: 田中)`）を自動抽出（WindowsのランダムID等は除外）。
    * **厳格な非侵入原則**: 認証パケット盗聴（Kerberos/SMB等）やARP偽装などの危険・違法リスクのある手法は完全に対象外とし、合法的かつ安全なパッシブ情報のみを活用。
23. **✨ インプレースDOMモーフィング（Idiomorph）によるスクロール・ホバー位置保持**
    * **スクロールリセットの完全解消**: バックグラウンドの定期スキャンや新規端末検知による自動リフレッシュ（30秒ポーリング）時でも、DOMツリー全体を破棄せず差分のみをインプレースで更新（DOM Morphing）。
    * **フォーカス・ホバーの継続**: 画面下方にスクロールして端末の詳細を確認している最中や、ホスト詳細ポップオーバー（ホバーカード）をマウスで閲覧している最中に更新が走っても、リスト先頭へのスクロールバックやホバーカードの消失を起こさず、快適に閲覧・操作を継続可能。
    * **完全自己完結**: 外部CDNに一切依存せず、Idiomorph拡張も単一バイナリ内に完全内包（Air-gapped対応）。

## 🚀 クイックスタートガイド

### 1. ダウンロード & インストール

[GitHub Releases](https://github.com/kh813/lanmap/releases/latest) からお使いのOS向けのZIPアーカイブをダウンロードして展開します。

* **macOS (Apple Silicon)**: `lanmap-mac-arm64.zip`
* **Linux (x64)**: `lanmap-linux-x64.zip`
* **Linux (arm64)**: `lanmap-linux-arm64.zip`
* **Windows (x64)**: `lanmap-win-x64.zip`
* **Windows (arm64)**: `lanmap-win-arm64.zip`

展開すると、即実行可能な **`lanmap`**（Windowsは `lanmap.exe`）が取り出せます。

```bash
# 例: macOS / Linux の場合
unzip lanmap-mac-arm64.zip
chmod +x lanmap
./lanmap start    # サーバー起動 (重複起動防止PIDロック付き)
```

> **💡 CLIコマンドについて**:  
> * `./lanmap`: 引数なしで実行するとヘルプ（USAGE）を表示します（誤操作・二重起動を防止）。
> * `./lanmap start`: サーバーおよびWeb UIを起動します。既に起動中の場合は重複起動を自動ブロックします。
> * `./lanmap stop`: 起動中の lanmap サーバーを安全に停止します。
> * `./lanmap status`: 現在の稼働状況（PIDやWeb UIポート）を確認します。

### 2. ブラウザでアクセス

ブラウザで **`https://localhost:3002`** を開きます。  
（※初回は自己署名証明書の警告が表示されますが、そのまま「アクセスを続行」してください）

### 3. 初期設定（3分で完了）

1. **画面左下の「⚙️ 設定画面」をクリック**:
   - Google Chat や Slack、Teams の Webhook URL を登録すると、未承認端末の検出時に即時通知されます。
   - 古い端末の自動クリーンアップ期間（デフォルト: 3日、最大7日推奨）も設定できます。
2. **サイドバーの「📋 台帳ホワイトリスト登録」をクリック**:
   - お手元のPC管理台帳（CSV/TSV）を貼り付けるかドラッグ＆ドロップすると、既存端末が一括で「🟢 承認済み」になります。
3. **右上の「⚡ Scan Now」をクリック**:
   - 手動でLAN内を即座にフルスキャンし、すべての端末を自動検出します。

## 🛠️ コマンド & 常駐サービス化

`lanmap` には、OS標準のバックグラウンドサービスとして常駐させるコマンドが内蔵されています。

```bash
# 通常起動 (フォアグラウンド実行)
./lanmap

# バージョン確認
./lanmap version

# 最新バージョンへの自動セルフアップデート (GitHub Releasesから自動取得・置換)
./lanmap update      # または ./lanmap upgrade

# サービス管理 (Linux: systemd / macOS: launchd / Windows: SCM)
./lanmap service install    # バックグラウンドサービスに登録
./lanmap service start      # サービス開始
./lanmap service status     # 稼働状態確認
./lanmap service stop       # サービス停止
./lanmap service restart    # サービス再起動
./lanmap service uninstall  # サービス削除
```

## ⚙️ 環境変数設定 (オプション)

| 環境変数名 | 説明 | デフォルト値 |
|---|---|---|
| `LANMAP_DATA_DIR` | DBファイル・TLS証明書の保存先ディレクトリ | 実行ファイルと同階層 |
| `LANMAP_PORT` | HTTPS待受ポート | `3002` |
| `LANMAP_SCAN_INTERVAL_MINUTES` | 定期スキャン間隔（分） | `2` |
| `LANMAP_SCAN_CONCURRENCY` | Ping並列送信数制限 | `20` |
| `LANMAP_LOG_LEVEL` | ログ出力レベル (`DEBUG` / `INFO` / `WARN` / `ERROR`) | `INFO` |

## 🏗️ ソースコードからのビルド

Go 1.22 以上がインストールされている環境で以下を実行します：

```bash
# ローカル用バイナリのビルド
make build

# 全OS向けZIPパッケージの一括生成
make cross-compile

# 単体テストの実行
make test
```
